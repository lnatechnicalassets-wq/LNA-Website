# 30. UI System & Accessibility Engineering Rules

**Authority:** Blueprint Part 4; SRS Section 11, NFR-A11Y-01  
**Scope:** Applies to all layout, components, styling, responsive behavior, and accessibility.

---

## 1. Design Direction & Token Usage
- **Tone:** Calm, credential-focused, academic appearance with generous whitespace and clear hierarchy.
- **Colors & Tokens:**
  - All colors and typography derive strictly from `content/site/brand.json` via `src/styles/tokens.css` (generated by `pnpm tokens`).
  - No raw hex values, RGB values, or ad-hoc Tailwind colors in component files.
  - Primary colors represent main brand identity and primary actions; secondary accent colors are reserved for badges and secondary CTAs.
  - Status indicators (success, warning, danger, neutral) must **always** pair color with explicit text labels (SRS 11.1).

---

## 2. Responsive Breakpoints
Follow SRS Section 11.2 and Blueprint Section 4.6 exactly:
- **Mobile (`320px` to `599px`):** Single-column layout, compact navigation, stacked cards, full-width inputs, zero horizontal scrolling in core learner journeys.
- **Tablet / Small Desktop (`600px` to `1023px`, Tailwind `sm`):** Two-column card layouts, collapsible admin drawer navigation, prioritized table columns.
- **Desktop (`1024px+`, Tailwind `lg`):** Full persistent navigation, fixed admin sidebar, detailed operational tables.

---

## 3. Component Inventory
All components live strictly under `src/components/` and are organized by functional domain:
- **`components/ui/`:** Base primitives (Radix-backed dialogs, dropdowns, tabs, accordions, buttons, badges).
- **`components/public/`:** `SiteHeader`, `SiteFooter`, `HeroSlider`, `CourseCard`, `BatchCard`, `EventCard`, `MentorCard`, `ReviewCarousel`, `PartnerStrip`.
- **`components/forms/`:** `Field`, `TextInput`, `Select`, `Checkbox`, `ConsentCheckbox`, `ErrorSummary`, `SubmitButton`, `OtpInput`, `TurnstileWidget`.
- **`components/portal/`:** `PortalShell`, `Sidebar`, `StatCard`, `AnnouncementCard`, `ReceiptCard`, `CertificateCard`.
- **`components/admin/`:** `DataTable`, `FilterBar`, `Pagination`, `ConfirmDialog`, `DraftPublishBar`, `DependencyWarning`.

*Rule R6:* Search existing components before creating new ones. Extend existing primitives rather than duplicating.

---

## 4. WCAG 2.2 AA Accessibility Checklist
Every page and interactive component must satisfy the following criteria:
1. **Contrast (1.4.3, 1.4.11):** Body text must achieve at least 4.5:1 against its surface; interactive controls and focus rings must achieve at least 3:1.
2. **Keyboard Navigation (2.1.1, 2.4.3):** All interactive elements must be focusable and operable via keyboard. Dialogs must trap focus when open and restore focus upon dismissal.
3. **Focus Visibility (2.4.7, 2.4.11):** Two-tone focus rings must remain clearly visible and never clipped or obscured by sticky headers.
4. **Touch Target Size (2.5.8):** Minimum interactive target size of 24x24 CSS pixels, expanding to at least 44x44 CSS pixels on mobile touch targets.
5. **Reduced Motion (2.2.2, 2.3.3):** Autoplay is disabled. All animations and carousel movements must honor `@media (prefers-reduced-motion: reduce)`.
6. **Error Identification (3.3.1, 3.3.3):** Form validation errors must be displayed beside the invalid field with an `ErrorSummary` at the top of long forms.
7. **Automated Audit:** Every public page and portal journey must pass automated `@axe-core/playwright` scans with zero serious or critical violations.
