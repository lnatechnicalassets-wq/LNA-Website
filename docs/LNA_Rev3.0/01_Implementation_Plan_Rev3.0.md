### Mandatory concurrency and failure-mode matrix

| Scenario | Expected invariant |
|---|---|
| Two applicants compete for final fixed seat; staff also adds concurrently | At most allowed occupancy, no overbooking; rejected attempt does not create ghost seat. |
| Capacity lowered while checkout reserves seat | Batch lock and floor prevent lower-than-occupied/reserved capacity. |
| Switch Off during valid checkout | Existing eligible session may finish, new intake blocked; deadline never alters switch. |
| Late receipt after hold expires and seat available | Verify and record, auto-confirm if otherwise eligible. |
| Late receipt after batch full/archived/completed or application cancelled | Keep receipt, do not auto-confirm ineligible/cancelled application; Needs Attention. |
| Late receipt conflicts with newly registered normalized contact | Persist verified financial evidence despite uniqueness conflict; no unauthorized duplicate admission. |
| Repeated callbacks/rechecks for same payment | One receipt and one admission effect. |
| Two distinct verified receipts for one enrollment | Both true receipts retained, one admission, additional payment flagged, no duplicate event counting. |
| Execute timeout, callback missing or worker crash | No blind second money movement; query and resolve or flag; preserve attempt identity. |
| Cancel, move, confirm concurrently | Deterministic lock order/atomic transitions; no lost payment, double seat or partial transfer. |
| Admin tries Super Admin action or client forges actor | Server and DB deny; no privileged mutation or false audit. |
| Concurrent last-Super-Admin demotion/deactivation | At least one active Super Admin remains. |
| Duplicate scheduler/email send, unknown response or provider quota exhausted | No duplicate intent, unknown not auto-retried, queue retained, no effect on admission. |
| Shared contact exception plus later public application | Audit exception preserved without creating public bypass; no PII leak. |
| Media replace/withdraw and concurrent reference update | No deletion of referenced image, no unintended draft exposure; bounded cache behavior tested. |
| Question configuration changes after submitted admission | Old answers remain interpretable, both forms use same current rules. |
| Repeated receipt generation, callback, resend, or batch move | One canonical collection and receipt number, historical snapshot preserved; no duplicate money. |
| Manual payment correction / PDF generation or attachment failure | Versioned corrected document, original preserved; send remains recoverable; no rollback of committed collection or admission. |
| Free/full-waiver admission or unauthorized receipt download | No payment receipt for zero collection; protected document access denied. |
